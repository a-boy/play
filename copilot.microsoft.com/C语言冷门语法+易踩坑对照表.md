## 🧩 语法与历史冷知识
- **C 语言的前身还有个“New B”**  
  在 BCPL → B → C 的进化链中，其实还夹着一个短命的“New B”，它是 Dennis Ritchie 在 PDP-11 上改造 B 语言时的过渡版本。
- **`extern` 在函数声明中是多余的**  
  因为函数默认就是全局可见的，加不加 `extern` 对效果没影响。
- **`sizeof` 是运算符，不是函数**  
  它可以直接写成 `sizeof variable`，而不是必须 `sizeof(TypeName)`。

---

## 🔍 语法怪招
- **数组下标可以反过来写**  
  `arr[2]` 和 `2[arr]` 完全等价，因为它们本质是 `*(arr + 2)`。
- **替代符号**  
  早期 IBM 键盘没有中括号 `{}`，所以 C 语言允许用 `<:` `:>` 代替 `[]`，`<%` `%>` 代替 `{}`。
- **字符串自动拼接**  
  `"C "` `"C++"` 会在编译期直接合并成 `"C C++"`，中间不需要 `+`。
- **空格有时会改变语义**  
  `a = *x/*y;` 和 `a = *x / *y;` 是两回事，前者可能被解析成注释。

---

## ⚙️ 运算与数据类型
- **“趋近运算符”假象**  
  `while(0<--x)` 看起来像有个 `-->` 运算符，其实是 `<` 和 `--` 连在一起的巧合。
- **`long` 不一定比 `int` 长**  
  在 Win64 下，`int` 和 `long` 都是 4 字节；在类 Unix 64 位系统中，`long` 才是 8 字节。
- **C99 支持不定长数组**  
  可以写 `int a[n];` 或 `int a[*];`（几乎没人用）。
- **数组作函数参数必须指定列数**  
  `void func(int a[][10]);` 是对的，但 `int a[][]` 是非法的。

---

## 🎯 其他有趣细节
- **常量字符串不能跨行**  
  除非用 `\` 续行符，而且 `\` 必须在行尾。
- **指针声明优先级陷阱**  
  `point *p[3]` 是“指针数组”，而 `point (*p)[3]` 是“指向数组的指针”。
- **`const int* p` 与 `int const* p` 等价**  
  都是“指向常量的指针”，而 `int* const p` 才是“常量指针”，“指向指针的常量”。

## 🛠 C 语言冷门语法 & 易踩坑对照表

| 冷门语法 / 特性 | 易踩坑点 | 示例代码 |
|---|---|---|
| **逗号运算符 `,`** | 优先级极低，且返回最后一个表达式的值，常被误解为分隔符 | `int x = (1, 2, 3); // x = 3` |
| **条件运算符嵌套** | `?:` 优先级低于赋值运算符，嵌套时需加括号，否则逻辑错乱 | `int a=1,b=2; int x = a>0 ? (b>0 ? 1 : 2) : 3;` |
| **数组名退化为指针** | `sizeof(arr)` 在函数参数中会变成指针大小，不是数组大小 | `void f(int arr[]){ printf("%zu", sizeof(arr)); }` |
| **指针算术** | `p+1` 增加的是 `sizeof(*p)` 字节，不是 1 字节 | `int a[3]; int *p=a; p++; // 跳过一个 int` |
| **字符常量类型** | `'a'` 是 `int` 类型，不是 `char`，可能导致比较或赋值出错 | `printf("%zu", sizeof('a')); // 通常是4` |
| **字符串字面量常量性** | `"abc"` 是 `const char[4]`，修改会导致未定义行为 | `char *s="abc"; s[0]='x'; // UB` |
| **结构体内存对齐** | 编译器会插入填充字节，`sizeof` 可能大于成员总和 | `struct S{char a; int b;};` |
| **位域（Bit-field）** | 跨平台布局不一致，依赖实现，移植性差 | `struct { unsigned a:3; unsigned b:5; };` |
| **隐式函数声明（C89）** | 在 C99 及之后已废弃，未声明直接调用会编译错误 | `printf("%d", foo()); // foo 未声明` |
| **`static` 局部变量** | 只初始化一次，函数多次调用会保留上次值 | `void f(){ static int x=0; x++; }` |
| **`volatile` 关键字** | 防止编译器优化，常用于硬件寄存器或多线程共享变量 | `volatile int flag;` |
| **`restrict` 限定符** | 告诉编译器指针不别名，提高优化，但错误使用会出错 | `void f(int *restrict a, int *restrict b);` |
| **复合字面量（C99）** | 可在表达式中创建匿名数组/结构体 | `int *p = (int[]){1,2,3};` |
| **`_Generic`（C11）** | 实现类型选择的宏，类似函数重载 | `#define type(x) _Generic((x), int:"int", double:"double")` |
| **灵活数组成员（C99）** | 结构体最后一个成员可为不定长数组，需动态分配 | `struct S{int n; char data[];};` |
| **`goto` 与标签作用域** | 标签作用域是整个函数，跳转需注意变量初始化 | `goto L; int x=1; L:;` |
| **`sizeof` 不求值** | `sizeof(expr)` 不会计算 `expr`，即使有副作用 | `sizeof(x++); // x 不变` |
| **枚举溢出** | 枚举底层是 `int`，值可超出定义范围 | `enum E{A=1}; enum E e=1000;` |
| **宏参数副作用** | 宏展开会重复求值，可能导致多次副作用 | `#define SQR(x) ((x)*(x)) // SQR(i++) 有坑` |

---

### 📌 使用建议
1. **多加括号**：尤其是运算符优先级不熟悉时。
2. **开启编译警告**：`-Wall -Wextra` 能提前发现大部分坑。
3. **熟悉标准版本差异**：C89 / C99 / C11 / C17 在语法上有不少变化。
4. **避免依赖实现细节**：如位域布局、结构体填充等。
